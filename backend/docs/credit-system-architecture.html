Backlyst Credit System Architecture

Ei document ta current codebase onujayi Backlyst er credit system er full architecture, schema, table relationship, business rule, ar current implementation behavior explain kore.

Scope: Ei document e shudhu credit-related schema ar shared table er credit-relevant field gula include kora hoyeche. Shared domain table jemon User, Subscription, PlacementTask, Website er full business field na diye credit-relevant part explain kora hoyeche.

1. System Overview

Credit system hocche ekta point wallet + task settlement + audit trail system. User task post korte credit spend kore, provider task complete korle earned credit pete pare, ar sob movement audit hishebe CreditLog table e save hoy.

Main Credit Sources

  • Subscription credits: batch-wise store hoy, expire korte pare
  • Earned task credits: provider earn kore, requester spend korte pare
  • Visibility credits: schema te ache, current active flow e kom use hocche

Main Credit Consumers

  • Requester task create/post flow
  • Task final settlement
  • Admin adjustment
  • Refund and reversal scenarios

2. Technical Dependencies

  • PrismaService diye sob credit DB read/write hoy
  • CreditModule app-level module hisebe register kora
  • AuthService user create somoy wallet create kore
  • TaskRequesterService task cost ar reserve amount calculate kore
  • ProviderTaskService final credit settlement cost decide kore
  • CreditTaskService actual deduct/refund/reward execute kore
  • CreditService summary and statement provide kore
  • ReferrerService referral progress read kore

6. Table Relationships

  • One User has one UserCreditWallet
  • One UserCreditWallet has many SubscriptionCreditBatch
  • One UserCreditWallet has many CreditLog
  • One Subscription can generate many SubscriptionCreditBatch
  • One PlacementTask can have many CreditLog entries
  • One UserReferral can have many ReferralReward rows
  • One UserReferral can also be referenced by many CreditLog rows
  • One Website can be linked to many CreditLog and referral records

7. Business Rules

7.1 Credit Cost Rules

Task Type Initial Cost Reserve Rule Final Settlement
BACKLINK_INSERTION 1 1 reserve Final cost 1
GUEST_POST 2 2 reserve Final cost 2
FLEXIBLE 2 2 reserve Final type backlink hole 1, guest post hole 2

7.2 Spend Order

  • Default e age subscription credits use hoy
  • Subscription enough na hole earned credits fallback hishebe use hoy
  • Caller chaile explicit SUBSCRIPTION ba EARNED source force korte pare

7.3 Refund Rules

  • Original source earned hole refund earned wallet e back jay
  • Original source subscription hole active batch e back jay
  • Refund operation o ledger e REFUND action hishebe record hoy

7.4 Provider Reward Rules

  • Provider reward always earned wallet e jay
  • Usually provider reward amount = final task cost
  • Reward operation TASK_COMPLETION reason e log hoy

7.5 Referral Rules

  • Referral stage tracking ache: signup, website verified, first backlink accepted, paid subscription
  • Stage-wise reward breakdown table ache
  • Current codebase e progress read implemented, full reward issuance flow visible na

8. Runtime Flow

8.1 User Registration Flow

  1. User create hoy
  2. System UserCreditWallet create kore with zero balance
  3. Tarpor user future spend/reward/refund receive korte pare

8.2 Task Spend Flow

  1. Task create time creditCost and reservedCreditAmount calculate hoy
  2. Credit deduction request ashe CreditTaskService e
  3. Task id valid kina check hoy
  4. User wallet load hoy, na thakle create hoy
  5. Subscription batch load hoy and oldest expiry first spend hoy
  6. Spend log CreditLog e save hoy

8.3 Task Delivery Settlement Flow

  1. Provider submit korle final task type determine hoy
  2. finalCreditCost set hoy
  3. providerRewardCredits set hoy
  4. Requester spend and provider reward alada credit operations diye execute hote pare

8.4 Statement Flow

  1. User statement request kore
  2. Optional filter apply hoy: type, action, reason, website, date range
  3. Paginated CreditLog rows return hoy

10. Current Implementation Notes

Important: Current codebase e schema and core credit operations implemented, but kichu orchestration gap ache.

  • Task service cost calculate kore, kintu actual wallet movement separate credit service call diye hoy

11. Plain-English Summary

Short e bolle, Backlyst er credit system hocche user er task point wallet. Requester task korte point spend kore, provider task finish kore point earn kore, subscription thakle batch-wise point use korte pare, ar sob movement ledger e save hoy. Ei structure ta future e referral, expiry, admin adjustment, ar analytics support korar jonno design kora.
